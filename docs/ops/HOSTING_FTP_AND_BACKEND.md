## FTP hosting (frontend) + VPS backend: как “связать” URL

В этом проекте фронтенд (Vite) **подставляет URL API на этапе сборки** через переменную окружения `VITE_API_URL`.

### 1) Куда писать адрес backend

Фронт ожидает, что `VITE_API_URL` указывает на базовый API путь вида:
- `https://api.example.com/api`

В коде это используется, например, в `src/services/api/http.ts`.

### 2) Как собрать под FTP (когда вы “кидаете index.html + assets”)

У вас уже есть скрипт:
- `npm run build:ftp`

Он делает `vite build --mode ftp` и (через `vite.config.ts`) выставляет `base: './'` — это то, что нужно для FTP.

Дальше вам нужно локально создать файл **`.env.ftp`** (он не коммитится) и прописать:

```env
VITE_API_URL=https://api.example.com/api
```

Затем:

```bash
npm run build:ftp
```

И загружаете содержимое `dist/` на FTP-хостинг.

### 3) Монорепа или разделять frontend/backend?

**Рекомендация для вашего текущего масштаба**: оставить **один репозиторий**.

Почему:
- проще поддержка (одна версия, одна документация, один набор изменений)
- вы деплоите “двумя способами”, но из одного источника:
  - `dist/` → FTP hosting
  - `server/` → VPS (systemd)

Когда имеет смысл разделять:
- разные команды/релизы, разные CI/CD пайплайны
- нужно отдавать backend как отдельный продукт/API

### 4) Куда класть SQLite на VPS

По умолчанию SQLite лежит в `server/var/app.sqlite` (создаётся автоматически).

Если хотите хранить DB вне репозитория — задайте:

```env
DB_PATH=/var/lib/opdemonstraions/app.sqlite
```
